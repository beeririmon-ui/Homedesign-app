# מעברים: כלים, פורמט ובדיקות (motion-agent, 2026-11-02)

התוכנית המלאה, ההחלטות והתקציב נמצאים ב-`docs/transitions-render-plan-2026-11-02.md`. רשימת עבודות הווידאו (מסלול R) נמצאת ב-`assets/prompts/transitions.nordic/route-r-jobs.json`. התיקייה הזו מכילה בינתיים רק את בדיקות הכלים על טיוטות שלב B. **אף נכס כאן לא עבר QA ולא נכנס לאתר.**

## הכלים (`site/tools/transitions/`)
| קובץ | מה עושה |
| --- | --- |
| `pan_reproject.py` | ה-pan בקוד: סיבוב טהור סביב מרכז העדשה, בהטלה מחדש (הומוגרפיה) של שני סטילס מאותה נקודה, עם תפר רך, השלמת "פער ה-pan", טשטוש תנועה סיבובי וחיתוך מובייל. פקודות: `pan`, ‏`compose` (פוזת סיבוב: המאסטר בכל מקום שהוא מכסה, הרינדור החדש רק ברצועה שנחשפה), ‏`check` (מדידת התאמה בחפיפה), ‏`register` (נעילת רינדור על ה-clay שלו), ‏`selftest` |
| `interp60.py` | אינטרפולציה ל-60fps בזרימה אופטית (DIS של OpenCV), ומבחן שמשווה כל מאנטרפל (גם RIFE או FILM, דרך `--candidate`) לפריימים המדויקים של pan |
| `export_seq.py` | חיתוך רצפי הפריימים לאתר (AVIF ו-WebP) ב-1920, ‏1080 ומובייל 3:5, ‏`manifest.json` ותצוגות mp4 של הנגינה המואטת |

**התקנה:** ‏Python 3.10 ומעלה, ‏`pip install numpy opencv-python-headless pillow` (‏Pillow 11.2+ כולל AVIF), ‏ffmpeg. בסשן הזה: `~/.venvs/motion/bin/python`.

```bash
T=site/tools/transitions
# בדיקה עצמית (סינתטית, על סטיל אחד)
python $T/pan_reproject.py selftest --src <still.png> --cam 12,0.52,0.46 --out <dir>
# התאמה בחפיפה של שני סטילס מאותה נקודה (yaw,u0,v0)
python $T/pan_reproject.py check --a D1.png --a-cam=-56,0.52,0.43 --b D2.png --b-cam=-91,0.52,0.43 --json out.json --sheet out.jpg
# נעילת רינדור על ה-clay שלו (אפיני גלובלי)
python $T/pan_reproject.py register --img d2.png --ref clay/D2.png --out d2-registered.png
# פוזת סיבוב (המאסטר + הרצועה מהרינדור החדש)
python $T/pan_reproject.py compose --a H0.png --a-cam 12,0.52,0.46 --b H0e-raw.png --b-cam 0,0.50,0.46 --out H0e.png --size 3840x2160
# ה-pan: קליפ במהירות קבועה (24fps, ‏8°/ש', כמו מקטע וידאו) ופריימי נגינה ב-60fps אחידים בהתקדמות, עם רצף מובייל
python $T/pan_reproject.py pan --a D1.png --a-cam=-56,0.52,0.43 --b D2.png --b-cam=-91,0.52,0.43 --kind master \
  --clip-dir clip --mp4 D1--D2.mp4 --play-dir play --play-s 1.4 --mobile-dir mobile --mobile-window 0.33,0.66
# רצפים לאתר
python $T/export_seq.py --desktop play --mobile mobile --out assets/frames/d1--d2.nordic --id P-D --from D1 --to D2 \
  --play-s 1.4 --mobile-window 0.33,0.66 --segments '[{"type":"pan","p":[0,1]}]'
```
`--kind pose` כשהסטיל השני הוא רינדור גולמי של פוזת סיבוב; `--a-overscan`/`--b-overscan` לסטיל שרונדר גבוה מ-16:9 (ראו "פער ה-pan").

## המודל הגאומטרי
מתוך `docs/house-plan.json` → `conventions`: ‏yaw חיובי שמאלה, ‏`f = (−sin yaw, −cos yaw)`, ‏`r = (cos yaw, −sin yaw)`, ‏`u = u0 + 0.6667 x/d`, ‏`v = v0 + 1.1852 (Hc − Z)/d`, מצלמה ישרה. ההומוגרפיה בין שני סטילס מאותה נקודה: `H = K_dst · R_dstᵀ · R_src · K_src⁻¹`, ומרכז הפיקסל ב-`u·W − 0.5`. שינוי ה-shift בתוך pan מדויק (K שונה בשני הקצוות).
**אומת מול צינור ה-clay** (‏`build_house.py set_view`, מצלמה משוקפת): ‏D1 → D2 של סבב 3 (‏3840, ‏35°) נוחת על D2 בסטייה של 0.5 פיקסל ב-1920 (בפסים 0.13–0.14), ‏B1 → B2 בסטייה של 0.6. הערבוב 50/50 חד, בלי צל כפול (`test-2026-11-02/check/clay-D1-D2.jpg`).

## תפרים
- **קצוות מדויקים:** הפריים הראשון הוא הסטיל הראשון והאחרון הוא השני (או הפוזה המורכבת), באותו שינוי גודל שבו האתר מקבל את המאסטר.
- **תפר נע:** בחפיפה, תפר רך (4% מהרוחב) עובר על הפריים מהקצה שבו נכנס התוכן החדש אל הקצה השני, ומהר במיוחד באמצע ה-pan (שם גם הנגינה הכי מהירה). בפוזת סיבוב שני הסטילס זהים מחוץ לרצועה, ולכן התפר לא נראה; בין שני מאסטרים (‏P-D, ‏P-B) הוא "מחיקה" רכה, שנראית רק איפה שהמאסטרים שונים.
- **בפוזה המורכבת** התפר קבוע בעולם (זווית אזימוט), 0.4% בתוך הקצה של המאסטר, ברוחב 4%. כך הפוזה ששומרים כסטיל והפריים האחרון של ה-pan זהים.

## פער ה-pan
בין שני הצירים, המבט הביניים רואה פס דק מעל הקצה העליון ומתחת לתחתון שאף סטיל לא מכסה: ‏`(sec(Δ/2) − 1)` מהמרחק בין האופק לקצה. ב-1080: ‏12–13° כ-3–4 פיקסלים; ‏21–25° כ-8–14; ‏33–35° כ-20–30 (‏P-D: ‏22 למעלה ו-30 למטה). הכלי משלים אותו ב-inpainting (Telea), וזה מספיק עד כ-12 פיקסלים. **הפתרון במקור:** פוזות ומאסטרים שמשתתפים ב-pan של 21° ומעלה מרונדרים עם 3% תוספת גובה למעלה ולמטה (אותה מצלמה, אותו מוקד; ה-16:9 הוא החיתוך המרכזי). ‏`selftest` מראה שהפער נעלם (0 מול 0.49% מהפריים ב-pan של 25°).

## פורמט הפלט לאתר
- **מאסטר:** `assets/video/<from>--<to>.nordic.mp4` (‏H.264, ‏60fps אחרי האינטרפולציה, בלי אודיו); הקליפים הגולמיים ב-`assets/video/raw/<clip>.<model>.mp4`.
- **רצפים:** `assets/frames/<from>--<to>.nordic/{1920,1080,mobile}/0001.avif` (ו-`.webp`), ‏`manifest.json`. ‏`<from>` ו-`<to>` הם מזהי הפריימים באותיות קטנות (`h0--m0`, ‏`d1--d2`, ‏`c0--k-boy`). מעבר הפוך = אותם פריימים מהסוף להתחלה.
- **הפריימים אחידים בהתקדמות לאורך המסלול** (מהירות קבועה בתוך מקטע, מהירות תואמת בחיבורים), ב-60 לשנייה של זמן הנגינה. ה-easing של ה-Bible מוחל בנגן (‏`manifest.easing`). ‏WebP במובייל: כל פריים שני (30fps), כגיבוי בלבד.

| גרסה | גודל | איכות AVIF / WebP | נמדד ב-P-D (‏1.4 ש', ‏84 פריימים) | לכל 2 ש' |
| --- | --- | --- | --- | --- |
| 1920 | 1920×1080 | 55 / 75 | ‏3.69MB / ‏4.10MB | ‏5.3MB |
| 1080 | 1080×608 | 50 / 72 | ‏1.41MB / ‏1.78MB | ‏2.0MB |
| mobile | 648×1080 (3:5) | 40 / 60 | ‏0.83MB / ‏0.67MB | **‏1.18MB** (יעד 1.5MB) |

לשם השוואה, אותו מעבר כווידאו עם GOP קצר: ‏mobile ‏H.264 ‏434KB, ‏AV1 ‏249KB; ‏1920 ‏H.264 ‏1.14MB, ‏AV1 ‏600KB (שאלה לאתר בתוכנית, סעיף 5).
