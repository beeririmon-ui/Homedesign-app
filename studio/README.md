# הסטודיו: ממשק ניהול פנימי

כלי פנימי (back-office) למעקב אחרי כל תהליך העבודה של המותג: החלטות פתוחות, חדרים ופריימים, מוצרים, דוחות QA ויומן. זה **לא** האתר ללקוחות, ואין לו קשר ל-`site/`.

הדף מתפרסם כ-claude.ai Artifact (המנהל מפרסם), כדי שאפשר יהיה לפתוח אותו מהטלפון ומאפליקציית Claude.

## בנייה מחדש

```bash
python3 studio/build.py            # בנייה רגילה
python3 studio/build.py --offline  # בלי רשת: מוצר בלי תמונה במטמון מקבל מקום שמור
```

- דרוש Python 3 ו-Pillow (בלי תלויות נוספות).
- הסקריפט רק **קורא** מהריפו ובונה מחדש את `studio/dist/` מאפס.
- תמונות המוצרים יורדות מ-CJ פעם אחת ונשמרות ב-`studio/.cache/p/`. גם ההמרות של הפריימים נשמרות ב-`studio/.cache/f/`. לכן בנייה חוזרת לא יורדת שוב לרשת.
- בסוף הריצה מודפסים מספר הקבצים והגודל. אם `dist` חורג מ-12MB או מ-240 קבצים, הסקריפט יוצא עם קוד 2.
- `studio/dist/` ו-`studio/.cache/` נמצאים ב-`.gitignore`.

| קובץ | מה |
| --- | --- |
| `studio/build.py` | קורא את כל הקלט ובונה את `dist/` |
| `studio/src/index.html` | הדף עצמו: HTML, ‏CSS ו-JS בקובץ אחד, בלי framework ובלי build step. ‏`build.py` מעתיק אותו ל-`dist/index.html` |
| `dist/data.json` | כל הנתונים שהדף מציג, מחושבים מהריפו |
| `dist/img/p/<id>.webp` | התמונה הראשונה של כל מוצר, 360px בצלע הארוכה, איכות 72 |
| `dist/img/f/<name>.webp` | פריימים ורינדורים, 1280px, איכות 78 |
| `studio/screens/` | צילומי מסך מהבדיקה המקומית |

### בדיקה מקומית

```bash
cd studio/dist && python3 -m http.server 8765
# ופותחים http://localhost:8765/
```

מקומית אין db, ולכן מסך ההחלטות מוצג לקריאה בלבד עם השורה "כדי לענות, פתח/י את הדף ב-claude.ai".

### פרסום (המנהל)

מפרסמים את `studio/dist/index.html` עם כל שאר הקבצים ב-`dist/` (‏`data.json` וכל `img/`) כקבצים נלווים באותם נתיבים יחסיים, ומצהירים על capabilities ‏`{db:{}, user:{}}`. אחרי הפרסום זורעים את collection ‏`decisions`: מסמך לכל החלטה, במזהה שלה (T1, ‏D1...), עם השדות של `status/decisions.json`. הדף עצמו לא זורע.

## מאיפה כל מספר מגיע

הכול מחושב ב-`build.py` מהקבצים, ושום מספר לא כתוב ביד.

| נתון | מקור וחישוב |
| --- | --- |
| חדרים ופריימים | `docs/house-plan.json` ‏`rooms[]`: כל חדר עם `slots_file`. חדרי הילד והילדה חולקים את `data/slots/kids.json` ולכן הם חדר אחד בסטודיו |
| עמדות | `data/slots/<room>.json` ‏`slots[]`. פריימים לכל עמדה: `frames` של העמדה, ואם אין (סלון) הפריימים של החדר. "רק במעבר": `slots_1_1.<room>.transit_only` בתוכנית הבית |
| שיוך מוצר לעמדה | לפי הנתיב: `data/products/<slot>/` הוא הסלון, ‏`data/products/<room-dir>/<slot>/` הוא חדר אחר (‏`entrance` = כניסה, ‏`dining` = מטבח ופינת אוכל), ו-`data/products/pool/` הוא המאגר המשותף |
| מועמדים משותפים | עמדה שהשדה `shared` שלה מפנה ל-`data/products/<dir>/` או ל-`data/slots/<room>.json <slot>` מקבלת גם את הכרטיסים משם. בטבלה הם מוצגים בנפרד ("+N ממאגר משותף") |
| מכוסה ב-3 מועמדים | עמדה שיש לה לפחות 3 כרטיסים שלא נדחו (ישירים ומשותפים) |
| נבחרים | כרטיסים עם `status: selected` |
| כפילויות | כרטיסים עם אותו `supplier.sku` או אותו pid (מתוך `product_url`) |
| תקנים CE / IP44 / EN71 | זיהוי טקסט בהערות בלבד. ברירת המחדל "לא ידוע". "לא מאומת" = מוזכר רק ליד "not verified", ‏"missing", ‏"no" וכו'. "מוצהר בהערות" = ההערות מצטטות הצהרה של הספק ("stated", ‏"PASS", ‏"certifications:"). זו לא תעודה |
| שלבים ויומן | `status/board.md`: הסעיפים "שלב N", הפריטים `[x]` / `[~]` / `[ ]`, ושורות היומן בפורמט `- תאריך · סוכן · טקסט`. נקודות אישור של המשתמש מזוהות לפי "**אישור משתמש**" / "**בחירת משתמש**" |
| החלטות | `status/decisions.json`, כגיבוי סטטי. החדרים של כל החלטה מוסקים מהטקסט (שם קובץ עמדות, שם חדר או מזהה פריים), או נלקחים משדה `rooms` אם יתווסף |
| commit | `git rev-parse --short HEAD`. אם יש בקלט קבצים שעוד לא נשמרו ב-commit, הם מופיעים בשורת הבנייה |

## המסכים

1. **סקירה:** כמה החלטות מחכות ומה חוסם, התקדמות לכל שלב 0–4 (ריבוע לכל משימה, מעוין לכל נקודת אישור של המשתמש), ספירת מוצרים לפי סטטוס, כרטיס לכל חדר (פריימים, עמדות, כמה עמדות עם 3 מועמדים ומעלה, החלטות פתוחות), 6 שורות היומן האחרונות, ומאיזה commit נבנה הדף.
2. **החלטות:** כרטיס לכל החלטה: השאלה, ההקשר, האפשרויות (המומלצת מסומנת), מה היא חוסמת, וסטטוס (פתוחה / נענתה / יושמה). פתוחות קודם, והחוסמות בראש. בוחרים אפשרות, מוסיפים הערה ושומרים. "לאשר את כל ההמלצות הפתוחות" פותח שלב אישור בתוך הדף. התשובה נכתבת ל-db כ-`update` עם `{status:"answered", answer:{option, note, at, by}}`. כשאין db, או שהוא ריק, ההחלטות מוצגות מ-`data.json` לקריאה בלבד.
3. **חדרים:** בוחרים חדר ורואים את הפריימים (סבב 2 המאושר, סבב 1 להשוואה, ובסלון גם הרינדורים). לחיצה על תמונה מגדילה אותה. מתחת: טבלת העמדות (מזהה, שם, קטגוריה, מיקום, פריימים, וריאציות נדרשות, מועמדים, נבחרים). לחיצה על מזהה עמדה פותחת את המוצרים שלה.
4. **מוצרים:** גריד עם תמונה, שם, עמדה, חדרים, עלות ב-USD, ימי משלוח, דוגמית של הצבע הדומיננטי, ספק וסטטוס. סינון לפי חדר, עמדה, סטטוס וספק, חיפוש טקסט, ומיון לפי עלות. לחיצה פותחת מגירה עם כל השדות, קישור לעמוד המוצר אצל הספק, שורת תקנים, כפילויות וההערות.
5. **איכות:** דוחות QA (`assets/qa/*.md`, ‏`qa/reports/*.md`) וסיכומי הליד (`data/leads/**/*.md`) בתצוגת markdown. הממיר הוא marked 12.0.2 מ-cdnjs. אם הוא לא נטען, מוצג הטקסט כמו שהוא. תמונות וקישורים יחסיים מהריפו מוצגים כשם קובץ.
6. **יומן:** כל שורות היומן מהחדשה לישנה, לפי תאריך, עם סינון לפי מי כתב (המשתמש, המנהל או סוכן) וחיפוש.

הדף זוכר בדפדפן רק דברים לנוחות: המסך האחרון, החדר, הסינון והדוח שנבחר.
